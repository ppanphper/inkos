# 会话消息的编辑与撤回

2026-11-19。目标：发错或想改一条消息时，可以编辑后重发或直接撤回，对话显示、模型上下文和作品文件一起回到该请求之前，不再需要停止后重打一条。

## 现状

- 会话记录是只追加的 `.inkos/sessions/<id>.jsonl`。被中止或失败的请求记为 `request_failed`，模型恢复上下文时只回放已提交的请求，所以模型本来就看不到它们；界面仍然显示，修正时要重打。
- 已提交的错误回合没有任何撤回途径，它写入的章节、设定和状态文件也留在作品里。
- 作品产物修订字段 `episodeId` 在实际数据里为空，无法据此判断某次请求改了哪些文件。

## 语义

- 撤回以一条用户消息为目标，含义是回到该请求开始之前：目标请求及其之后的所有请求一并撤回，不支持只撤回中间一条。
- 编辑等于撤回后用新内容重发。停止回复后，被停止的消息自动进入编辑状态，原文回填输入框。
- 撤回不删除或改写已有记录，只追加一条 `requests_rewound` 事件。模型上下文、界面消息和确认指令查找都忽略被撤回的请求。

## 作品文件回退

每个请求在开始和结束时各记录一份作品检查点（`request_started.workCheckpoint` 与 `request_committed/failed.workCheckpoint`）。检查点内容按 SHA-256 寻址，保存在 `.inkos/work-checkpoints/<workId>/<digest>.json`，内容相同的检查点共用同一文件。检查点包含：

- 作品清单中可回退的字段：标题、状态、来源关系、元数据；
- 每个产物的当前修订、候选修订和产物元数据；
- `source/` 下每个文件的内容哈希（SQLite 文件按逻辑备份计算，与修订校验和一致）。

确认式生产任务在任务开始前记录检查点，任务结束后的续跑请求以它作为开始检查点，使任务改动归入这次请求。

只有同时满足以下条件，文件才能回退，否则只能撤回对话，并说明原因：

1. 被撤回的每个请求都有开始和结束检查点，且属于同一作品；
2. 相邻请求首尾相接：前一请求的结束检查点等于后一请求的开始检查点，说明期间没有本会话之外的改动；
3. 当前作品清单和磁盘文件等于最后一个请求的结束检查点，说明之后没有其他会话或手动修改；
4. 需要恢复的每个文件都能找到相同哈希的内容：先查修订快照，再查检查点另存的内容。记录检查点时，没有任何修订快照保存的源文件内容（例如尚未登记的手动修改）会按哈希另存到 `.inkos/work-checkpoints/<workId>/blobs/`。

回退在作品写入锁内执行，一次原子提交：恢复源文件、删除基线之后新增的文件（SQLite 同时删除 `-wal`/`-shm`）、恢复清单字段和修订状态。之后新产生的修订保留为 superseded，可以追溯。

请求进行期间的改动无法区分来源：作者在请求运行时手动改的文件，会被当作这次请求的改动一起回退。因此提交前先把所有要覆盖或删除的文件（含 `work.json`）复制到 `.inkos/rewind-backups/<时间>-<会话>/`，路径记在撤回事件的 `backupPath` 里，对话框也会列出这些文件。

## 运行约束

- 会话中有聊天回复或后台生产任务在运行时，预览和撤回都返回 `SESSION_BUSY`；界面在刚停止回复时自动重试，等请求写完结束检查点。
- 回退文件时，同一作品上若有其他会话的回复、生产任务，或本进程内其他会话的 agent 回合在运行，返回 `REWIND_WORK_BUSY`；作品写入锁被占用时同样返回它。这时仍可以只撤回对话。
- 撤回进行中，该会话的新请求返回 `SESSION_REWINDING`。文件恢复之后若仍有新请求插入，撤回事件只撤回预览时确定的请求。
- 预览与执行之间若会话有了新请求，执行返回冲突，界面重新预览。
- 撤回追加事件后，缓存中的 agent 失效，下一轮从记录重建上下文。

## 接口

- `POST /api/v1/sessions/:id/rewind/preview`，参数 `requestId` 或 `clientRequestId`，返回将撤回的请求、对话轮数和文件计划。
- `POST /api/v1/sessions/:id/rewind`，额外参数 `restoreWork` 与 `expectedRequestIds`。

## 界面

- 用户消息悬停时显示编辑和撤回按钮；运行中不显示。
- 撤回已完成的回合，或撤回会改动文件时，弹窗列出轮数和文件，提供对话和文件一起回退（默认）、只回退对话、取消；只回退对话时注明文件保持不变。
- 只撤回一条被停止且没有文件改动的消息时，不弹窗。

## 已知限制

- 本功能上线前的请求没有检查点，只能撤回对话。
- 请求运行期间的手动修改会随请求一起回退，只能从备份找回。
- 其他进程（例如同时运行的 TUI）里的回合无法检测，只靠检查点比对和作品写入锁防护。
- 检查点和撤回备份不会自动清理，会随作品规模和请求次数增长。
- 新建作品的请求无法回退文件（基线时作品不存在）。
- 作品之外的状态（互动世界存档、`harness.sqlite` 中的执行记录）不回退；互动世界有自己的回合重做。
- TUI 暂未接入：TUI 没有中止功能，会话显示来自 `.inkos/session.json`，后续单独接入 core 接口。
- 旧版本程序读取含新事件的会话记录会报错，回滚程序版本前需要注意。
